Design — Data Model

How the data is structured in PostgreSQL. Does this cover everything you need to store?

users
id · name · email · phone · location · github_url · linkedin_url · portfolio_url
created_at · language_pref · consent_given_at
profiles — master resume data per user
id · user_id · work_experience (JSONB) · education (JSONB)
skills (JSONB) · projects (JSONB) · languages_spoken (JSONB)
is_complete · completion_score · updated_at
campaigns — one per job search (unlimited per user)
id · user_id · name · status (active/paused/completed)
broad_category (e.g. "Software Engineering")
sub_categories (JSONB — AI inferred: ["Mobile Dev", "Backend", ...])
profile_overrides (JSONB — campaign-specific emphasis)
email_monitor_since · created_at · last_run_at
job_listings — every job discovered by the scraper
id · campaign_id · source (jobspy/crawlee/greenhouse)
title · company · location · remote · url · apply_url
description · match_score · sub_category
discovered_at · status (pending/applying/applied/skipped)
applications — every job we actually applied to
id · campaign_id · job_listing_id · user_id
tailored_resume_pdf_url · cover_letter · form_answers (JSONB)
status (applied → responded → interview → offer / rejected / withdrawn)
applied_at · status_updated_at
email_events — every relevant email detected
id · application_id · campaign_id · type (interview/rejection/other)
subject · sender · received_at · raw_snippet
ai_reply_sent · ai_reply_body · ai_reply_sent_at
calendar_events — interviews added to calendar
id · application_id · email_event_id
title · scheduled_at · duration_minutes
calendar_provider · external_event_id · created_at

Does this data model look right? Anything missing or that doesn't make sense?
